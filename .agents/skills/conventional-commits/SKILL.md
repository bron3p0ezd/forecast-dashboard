# Conventional Commits

Use a Conventional Commit header:

```
<type>(<scope>): <imperative summary>
```

Use a scope when the affected area is clear, such as `backend` or `frontend`.

Follow the repository's established types:

- `feat`: new user-visible capability
- `fix`: defect correction
- `refactor`: behavior-preserving code restructure
- `docs`: documentation-only change
- `build`: build, dependency, or deployment configuration
- `chore`: maintenance or repository tooling

Write the summary in lower case, imperative mood, and without a trailing period. Keep it specific to the change.

Examples:

```
fix(backend): return 404 for unknown item rows
feat(frontend): add pagination to items list
docs: add backend env instruction
```

Before committing, inspect recent messages with `git log --oneline` and match the local scope and type conventions. Do not stage unrelated working-tree changes. Use `git commit --amend` to correct the most recent unpushed commit message when appropriate.
